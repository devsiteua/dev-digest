# DevDigest — local AI PR-review studio (and the L01–L08 course starter)

Four standalone packages, **no monorepo workspace**. Cross-package code is shared
through tsconfig path aliases over TypeScript **source**, not published modules.

## Stack

Node ≥22 · pnpm ≥10 (server, client) · npm (reviewer-core, e2e)
Fastify 5 + Drizzle + Postgres 16/pgvector · Next.js 15 + React 19 · Zod 3 · vitest 2

## Commands

```sh
./scripts/dev.sh                  # whole stack from zero (Postgres + API + web)
cd server && pnpm db:migrate      # REQUIRED manually — migrations do NOT run on boot
cd server && pnpm exec vitest run --exclude '**/*.it.test.ts'   # unit, no Docker
cd server && pnpm exec vitest run .it.test                      # integration, needs Docker
cd client && pnpm test && pnpm typecheck
cd reviewer-core && npm test      # npm, not pnpm
cd e2e && pnpm e2e:hermetic       # isolated stack on ports 5433/3101/3100
```

## Map

| Path | What |
|------|------|
| `server/` | `@devdigest/api` — Fastify, :3001. All I/O and persistence lives here |
| `client/` | `@devdigest/web` — Next.js, :3000. UI only |
| `reviewer-core/` | Engine: diff → prompt → LLM → grounded findings. **Zero I/O** |
| `e2e/` | Deterministic browser flows on agent-browser (not Playwright) |
| `server/src/vendor/shared/` | `@devdigest/shared` Zod contracts — **source of truth** |
| `client/src/vendor/shared/` | **Mirror copy** of the same (see Gotchas) |

## Conventions

- A contract lives in `@devdigest/shared` and doubles as request validation **and**
  response serialization schema. Do not hand-roll `.parse(req.body)` in handlers.
- Secrets are never in `AppConfig` and never in the DB. The single read chokepoint is
  `server/src/adapters/secrets/local.ts` (`~/.devdigest/secrets.json`, mode 0600).
- A test that touches the DB **must** use the `*.it.test.ts` suffix — CI splits the
  lanes by that glob.
- Every user-facing and repo file is written in **English**. Chat may be any language.

## Gotchas

- Changing a contract in `server/src/vendor/shared` requires the **mirror edit** in
  `client/src/vendor/shared`. The copies have already drifted — diff before committing.
- `docker compose down -v` destroys the volume with every imported repo and review.
- The DB schema is complete from day 1: an empty table (`skills`, `eval_*`, `memory`,
  `ci_*`, `multi_agent_runs`, …) is a future lesson, not dead code. Do not drop it.
- `.gitignore` references `agent-runner/` — that package does not exist yet (returns in L06).

## Do not touch

- `client/src/vendor/ui/**` — vendored design system; edit only on explicit request
- `server/src/db/migrations/**` — generated by drizzle-kit; new migration = `pnpm db:generate`
- the `.claude/skills/` entries listed in `skills-lock.json` — vendored from GitHub by hash.
  Hand-authored skills (`engineering-insights/`) are ours to edit.

## Session protocol

- **Before touching code:** read the `INSIGHTS.md` of the package the task names, and the root
  one. Treat entries as high-confidence guidance unless the code contradicts them.
- **Before wrapping up:** run `/engineering-insights`. Skip only when the session produced
  nothing that is not already written down — that is a normal outcome, not a failure.

## Read when

- You do not know the end-to-end review flow → read `docs/architecture.md`
- You confuse run / review / finding / blocker → read `docs/glossary.md`
- You start a lesson task → read `specs/README.md`, then that lesson's spec
- Something behaves unexpectedly → read `INSIGHTS.md` **before** digging into code
- You work inside one package → its `<pkg>/CLAUDE.md` (loads automatically by location)
